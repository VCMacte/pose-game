# Стена с позами — техника

Игра от первого лица для ребёнка 7 лет. Игра показывает позу, затем на игрока
едет стена с вырезом этой позы; ребёнок повторяет позу, камера судит
повторение. Игра на очки, забег ограничен по времени. Телефон на штативе видит
ребёнка камерой, картинка уходит на телевизор зеркалированием.

Здесь — только то, что нужно знать, чтобы менять код. Зачем всё устроено
именно так, с разбором задержки и обоснованием чисел, — в
[`docs/concept-and-plan.md`](docs/concept-and-plan.md). **Один факт живёт в
одном файле** — правило разобрано ниже.

**Кода пока нет.** Проект на стадии плана: спек утверждён, план реализации
написан, первая задача не начата. Поэтому строка «Код» у тем называет
*запланированные* файлы и говорит об этом прямо.
→ [`docs/superpowers/plans/2026-10-19-pose-game.md`](docs/superpowers/plans/2026-10-19-pose-game.md)

## Железо, под которое всё сделано

Телефон Redmi Note 11 Pro 5G (Snapdragon 695, Adreno 619), Chrome для Android,
задняя камера на игрока в ~2 м, на штативе. Телевизор — просто экран, картинка
уходит зеркалированием (Miracast / Samsung Smart View). Телевизор не умеет
ничего: вся логика, все датчики и всё состояние на телефоне.

Игрок — ребёнок 7 лет, рост 130 см; распознавание обязано работать и для
взрослого до 180 см. Комната жилая: посторонние люди и дети могут войти в кадр
во время забега.

## Устройство проекта

Vite + TypeScript, тесты vitest, зависимости из npm. Архитектура — порты и
адаптеры: `src/core/` (чистое), `src/adapters/`, `src/shell/`.
→ [`docs/architecture.md`](docs/architecture.md)

```
npm install --maxsockets 2 --no-audit --no-fund
npm run dev
npm test -- --maxWorkers=4
node tools/log-report.mjs <файл>   # числа забега из журнала с телефона
node tools/replay.mjs <файл>       # запись скелета через нынешнее ядро
node tools/make-sw.mjs             # пересобрать список кэша и поднять версию
```

Потолок воркеров в `vitest.config.ts` — не украшение: без него прогон форкает
по числу ядер и падает целиком с невнятной ошибкой.

## Как устроена эта документация

**В корне — то, что задевает ЛЮБУЮ правку, плюс индекс тем.** Разборы по темам
живут в `docs/`, по файлу на тему, и открываются по надобности. Система взята
из `run-game`, где монолитный `CLAUDE.md` дорос до восьмидесяти тысяч токенов в
каждой сессии: правка одной отрисовки платила за историю всех решений.

**Один факт живёт в одном файле, и правило двустороннее.** Тема не вправе
пересказывать корень, корень не вправе пересказывать тему; вместо пересказа —
ссылка. Разъехавшиеся копии одного числа — самый частый дефект такого проекта.

**У темы шапка:** заголовок, «Читать перед…» (по ней тему выбирают, НЕ открывая
файл — ею и достигается экономия), «Родитель» (обратная ссылка сюда), «Код»
(вход со стороны файла, который правят) и ссылка на замысел. У темы без
файлов-владельцев «Код» говорит это прямо: пропущенная строка неотличима от
забытой.

**Правка кода и правка темы едут ОДНИМ изменением.** Отложенная правка
документации неотличима от забытой, а устаревший разбор дороже дефекта — он
врёт уверенно.

**Разворот прежнего решения пишется абзацем, который НАЗЫВАЕТ отменяемый текст
и говорит, чем он опровергнут.** В этом проекте уже два таких разворота: знак
сдвига на задержку и источник звука — оба в
[`docs/concept-and-plan.md`](docs/concept-and-plan.md).

**Новая тема обязана попасть в индекс ниже.**

**Утверждённый спек заморожен.** `docs/superpowers/specs/2026-10-19-pose-game-design.md`
— исторический артефакт, он НЕ обновляется и живой правдой не является. Живая
правда — темы в `docs/`. Правка идёт в тему, не в спек.

## Инварианты, которые задевает любая правка

Здесь только то, что нельзя не знать, беря в руки любой файл. Разбор каждого —
в своей теме, и он не повторяется.

**Ядро не импортирует адаптеры и оболочку, и это проверяется тестом.** Ядро
обязано запускаться из node над записанным журналом — иначе разбор спорного
раунда требует переигрывания с ребёнком. Время приходит в ядро аргументом;
`performance.now` внутри ядра — дефект.
→ [`docs/architecture.md`](docs/architecture.md)

**`console.*` не используется в `src/` нигде.** Телефон на штативе, консоли
нет: вся диагностика идёт в журнал. Проверяется тестом.
→ [`docs/log-and-storage.md`](docs/log-and-storage.md)

**Приговор не вправе наказывать за то, чего игра не видела.** Худший класс
дефекта здесь — хуже падения: ребёнок не понимает, почему проиграл. Отсюда
знаменатель голосования из ВАЛИДНЫХ кадров, а не из всех; «не знаю» вместо
промаха при низкой `visibility`; и несудимый раунд вместо минуса при потере
игрока.
→ [`docs/judging.md`](docs/judging.md),
[`docs/presence-and-pause.md`](docs/presence-and-pause.md)

**Число, по которому СУДЯТ, и форма, которую РИСУЮТ, берутся из одного места.**
Фигура позы строится один раз из `PoseSpec` и идёт и в превью, и в маску
выреза. Две копии расходятся — и ребёнок не попадает в вырез, который видит.
→ [`docs/poses-and-figure.md`](docs/poses-and-figure.md)

**Сдвиг на задержку трансляции — ВПЕРЁД от касания стены, не назад.** Ребёнок
видит касание позже, чем оно случилось в игре, и позу держит под то, что видит.
Сдвиг назад удваивает рассинхрон. Это уже допущенная однажды ошибка, и на неё
стоит тест.
→ [`docs/judging.md`](docs/judging.md)

**Всё меряется в долях длины торса, а `x` домножается на отношение сторон
кадра.** MediaPipe нормирует `x` по ширине, `y` по высоте: без поправки углы
врут на десятки градусов, а отношение ширины плеч к торсу даёт 0.48 там, где
физически 0.86. Без известного `aspect` геометрия отказывается считать.
→ [`docs/camera-and-pose.md`](docs/camera-and-pose.md)

**Списки офлайн-кэша и номер версии ГЕНЕРИРУЮТСЯ** (`tools/make-sw.mjs`).
Правка руками не ломает разработку — там всё берётся из сети, — она ломает
установленное приложение у ребёнка и без сети.
→ [`docs/offline-and-build.md`](docs/offline-and-build.md)

**Прыжков и движений вдоль оптической оси камеры в игре нет вовсе.** Это
отсутствующие категории, не выключенные опции: вырез в стене — плоский силуэт,
и глубину он не показывает в принципе.
→ [`docs/poses-and-figure.md`](docs/poses-and-figure.md)
