# Судейство, окно и счёт

Читать перед правкой окна судейства, сдвига на задержку, порога голосования,
счёта, тактов раунда и выбора следующей позы.

Родитель: [`../CLAUDE.md`](../CLAUDE.md).
Код (запланирован, ещё не написан): `src/core/judge.ts`, `src/core/match.ts`,
`src/core/score.ts`, `src/core/picker.ts`, `src/core/round.ts`,
`src/core/run.ts`.
Замысел и обоснование чисел: [`concept-and-plan.md`](concept-and-plan.md).

## Четыре такта раунда

```
[1] ПРЕВЬЮ 2.0 с                схематичная фигура позы + её название + таймер-кольцо
[2] СТЕНА 2.0 с                 стена с вырезом едет от горизонта, к концу занимает экран
[3] ЗАМИРАНИЕ ≈ задержка тракта стена стоит у лица, цвет ещё не назначен
[4] ПРИГОВОР 0.8 с              заливка стены зелёным / красным / нейтральным
```

Такт раунда ≈ 5.0 с → около 18 поз за 90 секунд. Все длительности
настраиваются, кроме замирания: оно равно настроенной задержке и потому не
настраивается отдельно.

**Такт замирания существует не для напряжения.** Приговор физически недоступен
раньше `contact + latency` — см. ниже. Ребёнку это читается как удержание позы,
и это удачное совпадение, а не замысел.

## Сдвиг на задержку — ВПЕРЁД

```
окно судейства = [ contact + latency − 600 мс ,  contact + latency ]
```

Ребёнок видит касание стены на `latency` **позже**, чем оно случилось в игре, и
позу держит под то, что видит. Значит судить надо кадры, пришедшие **после**
игрового касания.

**Сдвиг назад удваивает рассинхрон вместо того, чтобы его снять.** Это уже
допущенная однажды ошибка — её разбор в
[`concept-and-plan.md`](concept-and-plan.md), раздел развороты. На знак сдвига
стоит отдельный тест, и он обязан падать при смене знака: ошибка невидима в
тесте «сдвиг сдвигает окно».

**Кадры отбираются строго по времени кадра, а не по номеру раунда.** При
задержке 400 мс и ходе стены 1.5 с окно уезжает за границу раунда и формально
перекрывает превью следующего; верные позы вне окна не имеют права давать `hit`.

## Правило приговора

- Кадр **валиден**, если присутствие не вернуло отказ и ориентация
  соответствует ожидаемой для этой позы.
  → [`presence-and-pause.md`](presence-and-pause.md)
- Кадр **совпал**, если выполнены **все** состояния, которые требует поза. Оси,
  которых поза не требует, не проверяются.
  → [`poses-and-figure.md`](poses-and-figure.md)
- Поза **засчитана**, если `совпавшие / валидные ≥ 0.60` и валидных `≥ 4`.
- Валидных `< 3` → раунд **не судится**: 0 очков, нейтральная заливка, `skip`.

**Знаменатель — валидные кадры, не все.** Кадры, в которых трекер потерял
ребёнка, не имеют права съедать очки; невалидные влияют только на порог
«≥ 4 валидных». При `валидные === 0` отношение считается нулём, а не делением
на ноль, и исход — `skip`.

При 11–12 Гц окно 600 мс даёт 7±1 кадр: 60 % — это 3 из 5 или 5 из 7.

## Счёт

Успех **+3**, провал **−2**, к общей сумме забега. Сумма **упирается в ноль** и
ниже не уходит: серия провалов в начале забега не должна загонять семилетнего
ребёнка в яму, из которой уже не выбраться. `skip` счёт не меняет вовсе.

Забег ограничен по времени: 60 / 90 / 120 с, по умолчанию 90. **Раунд,
начавшийся до истечения времени, доигрывается целиком.** Время забега стоит на
паузе.

## Выбор следующей позы

Чистая функция от генератора случайных чисел. Правила: не повторять предыдущую
позу, не выдавать её зеркало сразу за оригиналом, набирать только из
разрешённых ступеней (ступень N включает всё с ней и ниже).

**Выбор не хранит состояния «пул опустел».** Вместо этого тумблер словаря,
который уронил бы пул ниже трёх поз, блокируется в интерфейсе.
→ [`menu-and-settings.md`](menu-and-settings.md)

## Что уходит в журнал

Главное поле — `perAxis` в `round.judge`: по каждой оси попадание и **измеренное
значение**. По нему видно «левое плечо 58° при цели 90±30» без переигрывания
раунда. Ради этого судейство и возвращает измерения, а не один булев флаг.
→ [`log-and-storage.md`](log-and-storage.md)
