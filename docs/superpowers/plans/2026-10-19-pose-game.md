# Pose Game Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** PWA-игра, в которой ребёнок повторяет показанную позу, а едущая на него стена с вырезом этой позы засчитывает или не засчитывает повторение по данным камеры.

**Architecture:** Порты и адаптеры. Чистое ядро (нормализация точек, оси, набор поз, совпадение, голосование по окну, счёт, автоматы раунда и забега) не импортирует ни один адаптер и запускается из node над записанным журналом. Адаптеры — камера, воркер MediaPipe, рендер Canvas 2D, звук, журнал в IndexedDB, service worker. Оболочка — экраны и переходы.

**Tech Stack:** Vite, TypeScript, vitest, `@mediapipe/tasks-vision` (PoseLandmarker, модель `pose_landmarker_lite.task`), Canvas 2D, IndexedDB, WebAudio, service worker.

**Spec:** живая документация — темы в `docs/`, индекс в корневом `CLAUDE.md`. У каждой задачи ниже названа своя тема; читать только её, а не всё дерево. Утверждённый спек `docs/superpowers/specs/2026-10-19-pose-game-design.md` **заморожен** и годен лишь как исторический артефакт.

## Global Constraints

- **Ядро не импортирует адаптеры и оболочку.** Проверяется тестом на импорты, а не договорённостью (§7.1).
- **`console.*` не используется в `src/`** — телефон на штативе, консоли нет; только журнал (§8). Проверяется тестом.
- **Сдвиг на задержку — ВПЕРЁД:** окно судейства `[contact + latency − 600 мс, contact + latency]` (§3.1). Сдвиг назад — уже допущенная однажды ошибка.
- **Порог приговора:** `совпавшие / валидные ≥ 0.60` **и** валидных `≥ 4`; валидных `< 3` → `skip`. Знаменатель — **валидные кадры, не все** (§3.1).
- **Счёт:** успех `+3`, провал `−2`, сумма **упирается в ноль**; `skip` счёт не меняет (§3).
- **Ровно 13 поз, 18 вырезов с зеркалами** (§4.2). Прыжков и осей вдоль оптической оси камеры нет вовсе (§4.1).
- **В профильных позах левое и правое не различаются** — только ближняя/дальняя или «любая из рук». Точка с низкой `visibility` даёт «не знаю», а не промах (§4.3).
- **Полосы между состояниями осей** («не знаю») не считаются совпадением, но и не делают кадр невалидным (§4.4).
- **Буфер Canvas фиксированно 1280×720**, DPR игнорируется; в покадровом пути никаких теней, фильтров и градиентов (§5).
- **Журнал:** IndexedDB, потолки 25 МБ и 20 сессий, конверт `{t, type, ...data}`, `t` — целые мс от старта сессии (§8).
- **`vitest.config.ts` обязан нести потолок воркеров** (`poolOptions`/`maxWorkers`) — иначе прогон форкает по числу ядер.
- Пороги §4.4 — **стартовые**; живут в `src/core/config.ts` как данные, подлежат калибровке (§10.7).

## Review Focus

Пять классов входных данных, которые спек подразумевает, но ни один такт прямо не оговаривает. Тест на каждый добавлен в задачу, владеющую кодом.

1. **`lm === null` на любом шаге** — камера отдала кадр без человека. Ядро обязано вернуть «нет позы», а не упасть на обращении к точке. → Задача 3, 7, 8.
2. **Отношение сторон кадра приходит позже первых кадров или меняется на ходу** (смена камеры). Без него углы врут на десятки градусов. Нормализация обязана отказываться считать, а не считать неверно. → Задача 3, 11.
3. **Все кадры окна невалидны** — ребёнок вышел ровно на время судейства. `валидные = 0` не должно дать деление на ноль; ожидается `skip`. → Задача 9.
4. **Задержка 400 мс при ходе стены 1.5 с** — окно судейства уезжает за границу раунда и перекрывает превью следующего. Судейство обязано брать кадры по времени, а не по номеру раунда. → Задача 9, 12.
5. **IndexedDB недоступна** (приватный режим, исчерпана квота). Игра обязана играться без журнала: `broken = true` и ни одного исключения наружу. → Задача 13.
